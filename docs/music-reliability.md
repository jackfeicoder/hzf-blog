# 音乐可靠性（2026-10-07）

## 穷尽候选后才跳歌（2026-10-16）

- 播放时覆盖全部**已启用且声明支持相应平台**的脚本，搜索小云、小Q、小酷、小狗、小咪所有可匹配的备用平台；未启用源保留管理员的禁用状态。不同平台使用各自的真实歌曲 ID，仍校验歌名、歌手和已知时长。
- 遍历各脚本声明的兼容音质。对现有全豆要 `SOURCE_HANDLERS` 注册表，外层返回失效地址后，还会在一次性隔离容器中单独调用已审阅的内部候选分支。原脚本及数据库配置保持原样；任意第三方脚本未公开的内部协议不在自动适配范围内。
- 找到经过音频头和 HTTP 检查的有效地址立即返回，不要求收集齐歌词、封面才开始播放。小酷搜索补齐曲库查询参数，正常 20 条搜索即可找到《枫》的原唱条目，歌曲 ID 没有硬编码到应用中。
- `attempted` 只记明确失败的路线；超时、临时限流、503/504、冷却及备用元数据请求失败都表示尚未完成。`deferred` 单独保留待重试路线并移至后排，优先覆盖未访问的候选，防止首个超时接口反复占满预算。
- 每批仍保留 27 秒预算，执行容器最多两个并发；继续请求携带两份路线账本，不再限制总批数或浏览器换源次数。等待遵守服务端重试提示，暂停、切歌会停止旧歌曲的后续继续请求。
- 只有后端明确返回 `exhausted: true`，前端才自动下一首。网关 HTML、断网、请求预算用完及冷却都不是穷尽证据。服务持续故障时可暂停或手动下一首，页面不会把尚未测试的路线判为失效。
- 上线前实测：从小狗《枫》条目发起，新逻辑自动跨平台命中全豆要＋小酷 `118987`，128k、HTTP 206，读取 65536 字节并识别时长 275.667 秒。诊断只记录路线及结果，不保存第三方签名地址到公共文件。

## 缓存与延迟优化（2026-10-15）

- 播放地址持久保存在服务器 `backend/.runtime/music-addresses.sqlite3`，不设时间过期、不主动刷新，服务重启仍保留；只限制内存后备缓存为 500 条，不按容量淘汰磁盘地址。成功路线映射也不再按 7 天清除，确保备用平台命中可长期复用。缓存键包含音源摘要、真实平台 ID 和音质，重新导入脚本不会沿用旧缓存。
- 缓存命中优先于重新解析，生成新的同源不透明播放票据，不向浏览器暴露第三方签名地址。失效音频、截断传输及浏览器错误反馈立即清除地址；原路线支持强制刷新后再换源。
- 相同路线的并发解析合并为一个有时限的任务；单个调用取消不会取消其他等待者。只在私有文件中保存经过音频探测的媒体地址，不下载音频文件；不写入日志、公共 API 或浏览器持久存储。过期签名仍先尝试复用，失败后刷新。旧票据迟到的错误不会清除已替换的新地址。
- 失败歌曲/路线冷却 45 秒；同平台同音质 180 秒内至少三次失败、涉及至少两首歌后临时冷却 3 分钟。不修改管理员启停或排序；其他平台/脚本版本不受影响。全部候选冷却时给出重试提示，避免自动跳歌造成请求风暴。
- 保持无网络、非 root、只读容器和受限 HTTP 桥，隔离执行并发上限从 1 调至 2。补齐 console 分组、计时等无输出方法；不取消隔离、不执行宿主机音源脚本。
- 每条冷路线的解析与音频检查预算 10 秒，单请求保持 27 秒预算。已有成功路线优先；主路线较慢时延迟启动一次严格匹配的备用平台查询，先成功者返回。缓存命中时不触发额外备用查询。
- 小云搜索优先原平台元数据，2.5 秒未完成才使用第三方接口；浏览器音频缓冲看门狗放宽至 20 秒，降低短暂抖动误判。自动跳过失败歌曲、手动暂停与权限隔离保留。

参考 [落雪地址缓存与强制刷新](https://github.com/lyswhut/lx-music-desktop/blob/master/src/renderer/core/music/online.ts) 和 [备用匹配与请求合并](https://github.com/lyswhut/lx-music-desktop/blob/master/src/renderer/core/music/utils.ts) 的设计思路，未复制其实现。

本次基于线上源码快照实现，不修改管理员音源启停/优先级、站点透明度或歌单。数据库主文件结构保持不变。

## 换源与缓存

- 地址解析成功不等于音频可播。经过音频探测才保存地址，实际流开始后才记住成功路线；按歌曲、请求音质、音源脚本摘要、真正平台 ID 区分，不设时间过期。
- 先试成功路线，再根据各平台/音质近 24 小时的实播证据和管理员手动排序选择。失败路线降优先级 90 秒；已有成功证据的音源按实播成功/失败评分，没有成功证据的音源至少三首不同歌失败后才全局降分，不擅自关闭音源。
- 删除、关闭或重新导入后的音源记忆不再使用。第三方音频 URL 使用上述独立缓存，音频传输/浏览器反馈错误立即清除。
- 播放中断先刷新该路线一次，再排除该路线继续；保留播放位置和已加载歌词。每批解析最多 27 秒、单个冷候选最多 10 秒；前端持续携带已尝试和待重试列表，不按固定批数提前结束。
- 原平台慢或失败时，查询全部受支持的备用平台，严格核对歌名、歌手、已知时长，并用备用平台实际返回的 ID 解析音频。保留歌单原歌曲，不把平台 ID 互相套用。
- 音质按兼容清单降级，返回实际选择音质；歌词空响应仅缓存 15 秒，不长期锁死。

## 自动跳过失败歌曲（2026-10-08）

前端收到后端明确的全部候选耗尽标记后，才自动尝试播放队列中的下一首，不删除歌曲或修改收藏。单曲循环模式下也跳过失败歌曲；随机模式只选择本轮尚未失败的歌曲。整轮队列全部失败时暂停并提示，防止无休止循环。正常实播进度超过 3 秒后重置这一轮失败记录，手动重试/切歌也会开始新一轮。

用户暂停、切歌、退出账号后，旧请求不会触发自动切歌。浏览器自动播放限制、登录/权限错误、限流错误不触发批量跳歌；歌词缺失也不触发跳歌。

## 独立歌词

歌词并行获取，不阻塞音频。优先匹配实际播放版本及原歌曲，缺失时独立搜索同一录音的备用平台。失败不触发音频停止；切歌、退出账号和取消后的迟到结果不覆盖新歌曲。元数据接口故障不代表对应音源音频失效。

## 诊断和隐私

管理员的“音源管理 → 播放诊断”可查看近 24 小时健康统计及最近 100 条尝试（界面显示最近 30 条）。记录歌曲、音源、平台、音质、阶段、失败类别和耗时，不记录访客身份、私人歌单、播放地址或密钥。`/api/music/diagnostics` 与音源管理接口同样只允许指定管理员访问。

私有地址文件与路由证据文件位于 `backend/.runtime/`，目录 0700、文件 0600（Linux）。地址和成功路线不定时过期；诊断事件最多 1000 条、保留 7 天。不新增 Redis 服务。浏览器收到的短时播放票据仍是 30 分钟，与服务器长期地址缓存不同，票据失效后重新解析可命中服务器缓存。
