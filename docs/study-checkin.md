# 学习打卡

入口 `/study`，顶部「画图」右侧和移动端侧边菜单可访问。需要登录；所有任务、轮次、重点标记和笔记按用户保存。

## 每日规则

- 北京时间每日生成一次：Java八股最多 5 题、Hot100 最多 2 题、项目 1 项。
- 打开页面时生成任务，而不是后台定时自动跳进度。未完成题目按题库排序优先延续，错过几天也不跳题。
- 勾选、取消、重点标记立即保存，笔记离开输入框时保存。历史日期只读。
- 当天任务文本固定；编辑题目、增加题目、停用题目从下一天的任务生效，不重写历史。
- 各题库独立轮次，完成后手动开始全部复习或只复习重点，新轮次次日开始。开始后旧轮次归档，当天旧任务只读。
- 已完成轮次不加入新增题；下一轮使用更新后的题库。未完成轮次在生成下一天任务时纳入新增题。
- 私有 API 返回 `Cache-Control: private, no-store`。Cloudflare 如有「缓存所有内容」规则，仍须明确排除 `/api/study/*`，更建议排除整个 `/api/*`。

## 初始题库

Java 默认阅读《Java八股》，Hot100 默认阅读 `/post/5`。尚未导入具体题目时，使用每日 5/2 个普通打卡框；这些框只记录当日完成情况，不虚构题库数量或题目轮次。

管理员打开「题库维护」→ 选择 Java → 输入文章编号（留空自动查找标题恰好为《Java八股》的文章）→ 预览 → 勾选真实题目 → 确认导入。Hot100 默认文章编号为 5。

解析器识别 Markdown 编号条目，跳过代码块；答案内的编号可能被识别为候选，表格、复杂目录可能需要手工维护。预览不会写入数据库；只有确认选中的条目才写入。相同分类、标题、链接的重复导入会跳过。文章之后变化时，请编辑原题目的稳定编号；再次导入改名条目会视为新题目。

项目初始顺序 HelloAgent → paicli → RAG，各为一个可勾选的阶段任务。建议管理员将其拆成真正的章节或里程碑，按排序数字排列，停用原来的粗粒度阶段任务。

## 数据与验证

新增表：`study_items`、`study_rounds`、`study_progress`、`study_days`。应用启动通过现有 SQLAlchemy `create_all` 创建新表，不修改原有文章或用户表。部署前备份数据库。

题库停用而非删除；已有编号保留个人进度。每日 JSON 快照保存标题、答案、链接、完成情况与笔记。仅管理员维护公共题库，普通用户只读写自己的记录。学习记录暂不提供导出、补签和公开排行榜。
